# ModelDancer

Paper plugin (1.21.x) that displays animated 3D dancers through ModelEngine 4.

---

## Requirements

- Paper 1.21.x
- Java 21+
- ModelEngine 4.0.9

## Setup

1. Build the project or use the already built JAR.
2. Place the plugin JAR in the server's `plugins/` folder with ModelEngine 4.0.9 installed.
3. Start the server once to generate the required files and folders.
4. Copy the `.bbmodel` files that follow the guide into `plugins/ModelEngine/blueprints/`.
5. Reload the models with `/meg reload` or restart the server.
6. Download the resource pack generated by ModelEngine and add it to your own resource pack setup.
7. Start the server and enjoy.

For naming, animation, and model structure constraints, see [`docs/BBMODEL_INTEGRATION.md`](docs/BBMODEL_INTEGRATION.md).

## Quick Install (Development)

```bash
mvn clean package -DskipTests
```

Copy the JAR `target/ModelDancer-*.jar` into `plugins/` and restart.

## Commands

**Player dances**

| Command | Description |
|---|---|
| `/danse <style>` | Start a dance with your own skin |
| `/danse <style> <playerName>` | Start a dance using another player's skin |
| `/danse stop` | Stop the dance |
| `/danse list` | List the available styles |
| `/danse debug` | Enable or disable diagnostic logs |

**NPCs (static dancers)**

| Command | Description |
|---|---|
| `/danse npc spawn <id> <style> [playerName]` | Create an NPC at your position |
| `/danse npc move <id>` | Move an NPC to your position |
| `/danse npc delete <id>` | Delete an NPC |
| `/danse npc list` | List active NPCs |
| `/danse npc style <id> <style>` | Change an NPC's dance style |
| `/danse npc resize <id> <value>` | Resize an NPC (0.1 - 20.0) |
| `/danse npc highlight <id> [seconds]` | Highlight an NPC with particles |

Static dancers are saved automatically and restored on restart.

**Choreography** - synchronization of static dancer groups

| Command | Description |
|---|---|
| `/danse choreo create <groupId> <id1> [id2…]` | Create a group and synchronize the animations |
| `/danse choreo add <groupId> <id>` | Add a dancer to the group |
| `/danse choreo remove <groupId> <id>` | Remove a dancer from the group |
| `/danse choreo sync <groupId>` | Re-synchronize the group's animations |
| `/danse choreo delete <groupId>` | Delete the group (dancers return to solo mode) |
| `/danse choreo list` | List all groups and their members |

**Playlists** - scheduled animation sequences

| Command | Description |
|---|---|
| `/danse playlist create <id> [loop\|once]` | Create a playlist (looping by default) |
| `/danse playlist add <id> <style> <reps>` | Add a track (style × N repetitions) |
| `/danse playlist remove <id> <index>` | Remove a track by index |
| `/danse playlist delete <id>` | Delete the playlist |
| `/danse playlist info <id>` | Show the tracks in the playlist |
| `/danse playlist list` | List all playlists |
| `/danse playlist play <id> player [playerName]` | Start the playlist on a player |
| `/danse playlist play <id> dancer <dancerId>` | Start the playlist on a static dancer |
| `/danse playlist play <id> group <groupId>` | Start the playlist on a group |
| `/danse playlist stop player [playerName]` | Stop a player's playlist |
| `/danse playlist stop dancer <dancerId>` | Stop a dancer's playlist |
| `/danse playlist stop group <groupId>` | Stop a group's playlist |
| `/danse playlist active` | Show all active playlists |
| `/danse playlist debug` | Enable or disable playlist debug logs |

## Configuration

Dance styles are defined in `config.yml` without recompiling.
See [`docs/static_dancers.md`](docs/static_dancers.md) for static dancers and choreography, [`docs/playlists.md`](docs/playlists.md) for the playlist system, [`docs/menus.md`](docs/menus.md) for menu documentation, and [`docs/BBMODEL_INTEGRATION.md`](docs/BBMODEL_INTEGRATION.md) for model integration.

## Performance and Limits

### Concurrent Dances

| Config key | Default | Effect |
|---|---|---|
| `dance.maxConcurrent` | `500` | Maximum number of active player dances at the same time. Each dance allocates 1 `Dummy`, 1 `ModeledEntity`, and 1 `ActiveModel` in ModelEngine. Exceeding this limit sends `§cToo many active dances, try again in a moment.` to the player. Set it to `0` to disable the limit. |

### Skin Fetching (Mojang API)

Offline player skins are retrieved through the Mojang API on a dedicated thread pool. Profiles are cached for the session and trigger only one Mojang request per username.

| Config key | Default | Effect |
|---|---|---|
| `skinFetcher.maxThreads` | `4` | Size of the `DanseSkinFetcher-N` thread pool. Increase it if many skins are loaded at startup (static dancers with custom skins). |
| `skinFetcher.timeoutSeconds` | `5` | Maximum time to wait for a Mojang response. On timeout, the skin is ignored and a warning is logged. |

### Static Dancers

All static dancers and all choreography groups share **one single `BukkitTask`** (global tick at 1 tick per cycle) instead of one task per dancer. The number of scheduled Bukkit tasks is therefore constant no matter how many NPCs exist.
